BAS Fraud Engine
07 / Anti-Spoofing
Behavioral Anti-Spoofing · 11 Signals

Fraud at scale is boring, not theatrical.

The real attack isn't a dramatic GPS spoof. It's 50 riders sharing one device fingerprint from one hostel. We designed BAS to catch clusters, not just individuals.

BAS(c) = Σj=1..11 wj · fj(c),   Σ wj = 1,   fj(c) ∈ [0, 1]
#SignalWeightWhat it catches
1IMPOSSIBLE_TRAVEL0.18Haversine ÷ Δt > 120 km/h
2DEVICE_FINGERPRINT_REUSE0.15Same FP on ≥ 3 worker IDs
3VPA_COLLISION0.12Same UPI VPA on ≥ 2 profiles
4CLAIM_BURST_RATE0.10> 3 claims in rolling 24 h window
5GPS_JITTER_OUTLIER0.10Lat/lng std-dev anomalous vs. history
6ZONE_MISMATCH0.09Claim outside policy's insured zones
7TIMESTAMP_ANOMALY0.08Client clock skew > 5 min from UTC
8IP_ASN_SHARING0.07≥ 5 workers on one ASN in 1 h
9NEW_ACCOUNT_VELOCITY0.05Account < 72 h old with ≥ 2 claims
10PAYOUT_ACCOUNT_CHURN0.04Beneficiary VPA changed in 7 d
11PATTERN_SIMILARITY0.02Cosine similarity to known fraud ring

Payment Routing
08 / Payments
Real Razorpay + VPA-suffix routing

Real API calls. Real order_XXX IDs. Graceful fallback.

Gateway routing

// VPA suffix → gateway
*@paytm                    → Razorpay Orders API  (REAL)
*@upi, *@ybl, *@okhdfcbank  → UPI gateway          (mock)
card, *@stripe             → Stripe               (mock)
*@oksbi, *@ibl             → UPI gateway          (mock)
fallback                   → Razorpay Orders API  (REAL)

Why Orders API, not Payouts?

  • RazorpayX Payouts requires account activation — not available on test accounts.
  • Orders API is universal and returns a real order_XXX the judge can look up.
  • Settlement modeled out-of-band with realistic 1.8–3.2 s delay.

Live API call flow

POST https://api.razorpay.com/v1/orders
Authorization: Basic base64(KEY_ID:SECRET)
Content-Type: application/json

11 / Real-Time
Server-Sent Events · < 800 ms latency

Static dashboards feel like schoolwork.
Ours breathes.

6 typed event streams

red TRIGGER_FIRED — new disruption detected
amber CLAIM_CREATED — auto-claim minted
orange FRAUD_CHECKED — BAS score computed
green PAYOUT_SENT — Razorpay accepted
blue WORKER_REGISTERED — rider onboarded
purple POLICY_CREATED — coverage purchased

Implementation

// backend/services/events.service.ts
export class EventBus extends EventEmitter {
  emit(type: EventType, payload: T) {
    super.emit('event', { type, payload, ts: Date.now() });
  }
}

// backend/routes/events.routes.ts
router.get('/admin/events/stream', requireAdmin, (req, res) => {
  res.writeHead(200, {
    'Content-Type': 'text/event-stream',
    'Cache-Control': 'no-cache',
  });
  bus.on('event', e => res.write(`data: ${JSON.stringify(e)}\n\n`));
  // 30 s heartbeat to survive Cloudflare idle timeout
  setInterval(() => res.write(': hb\n\n'), 30000);
});

// frontend/hooks/useEventStream.ts
// auto-reconnect with exponential backoff

Each event animates into the feed (slide-in + fade). Live payout counter ticks upward on every PAYOUT_SENT — that's our "stop scrolling" demo moment.

The feedback loop

1

Worker taps "Report Condition"

Icons for Heavy Rain / Flood / Extreme Heat / Pollution / Strike. GPS auto-captured, severity slider.

Cluster detection

≥ 3 reports within 2 km + 15 min → provisional DisruptionEvent with source='community' → claims process immediately.

3

API confirmation

Later, when Open-Meteo / AQICN confirms the same event: boostTrustOnApiConfirm() fires.

4

Trust Score +50

Every original reporter earns +50 Trust Score. Honest reporting is rewarded; system gets more accurate.

Why this wins

No other team ships this.

We turn 1.2M riders into a distributed sensor network that outruns commercial weather APIs by minutes. Over time the system becomes more accurate than the upstream data it was bootstrapped on.
